利用 AI 智能体，回到 Orgmode 导出部署

2026-11-12约 1086 字

近段时间，書集工作暂停，业余时间花在了重构网站上。

使用 workbuddy 似乎会上瘾，之前用它做了一个 hugo 主题，自己的需求基本能完美实现，就想着能不能再让它做一个 orgmode 导出 html 静态文件的脚本，让之前因无技术能力而没能实现的想法呈现出来。没想到，真能做到。

结果就是目前网站的样子，样式还是用的之前 hugo 时的纸质风格主题。

1. 为什么退回#

上个月国庆期间才刚刚从 orgmode 转到 hugo, 简单作了记录，那时迁移的原因是 hugo 的主题生态与 orgmode 导出站点的技术能力不足。

而在使用 hugo 的过程中，我用了 ox-hugo 导出到 hugo 适用的 markdown 文件，也就是实际使用流程中多了一步，让自己感到有些麻烦。

原本一篇文章一个 orgmode 文件，写完就结束了，现在使用 hugo 还要多加一步导出，操作起来不那么流畅。对于学习 ox-hugo 相关功能有点缺乏耐心。

当然 ox-hugo 也有另一种模式，所有文章写在一个 orgmode 文件，子标题导出 markdown 文章。虽然有好处，比如一个主题的文章可以写在一起，但文章间的链接，我没怎么学会。

总之，就是习惯了写一篇就丢的模式，转变流程后不适应。

2. 怎么迁回的#

一个偶然的机会看到 tianheg 的站点，发现他从 hugo 回到了纯 orgmode ，在看他的 git 仓库时感觉似乎也是通过 AI 协助的。

所以就让 workbuddy 试了试。结果还真出人意料，真的可以的，既保留了之前手搓的 orgmode 导出 html 的功能，又增加了在 hugo 时的 prettyurl 、 tags 、 相关文章、往年今日等模块，甚至样式都能一样。

而且，还让 workbuddy 对代码进行优化，提高了导出效率，比之我曾经手搓的快了不了，也能使用 codeberg 的 CI 功能，写完只需 git 推送，其他的一切交给机器即可。

这是 AI 时代应有的，效率交给机器，人来呈现情感与创意。

3. 实现的一些功能#

本站本质上只有一堆 html 静态文件，与 hugo 等静态网站生成器实现的一致。相对于直接用 orgmode 的 ox-publish 导出，增加了以下功能：

  • 标签 tags ，取自头文件中的 #+TAGS: ，增加一个 tags 页面。
  • 文章页 上一篇/下一篇 导航， 相关文章 与 往年今日 模块，显示6篇文章（如有）。
  • 评论功能，使用 cwd 实现，部署在 cloudflare，速度似乎有些慢；并加了 webmention 功能，然并不不知道 webmention 有没有效果。
  • 搜索功能，似乎是 js 实现的，偶尔会加载不了，不管了，先这样吧。
  • 订阅功能，包括全站与各个分类。

技术是没有的，能做到这个程度我已经很满意。

4. 纯文本记录#

人老了，少了向上向前的野望，却更容易回忆往昔，一个安稳的顺畅的写作环境是很好的保障，如今终于通过 AI 智能体实现了。

经过这次折腾，想像中的纯文本记录可以比较舒适地开展了。当前写博客的流程就非常简单：打开编辑器–>码字–>保存–> Git提交。

接下来就是文章再整理整理，把曾经的一些文字能搬的都搬上来，其中的一些错误修复，再慢慢增加点文字。将站点作为自己在网络时代的数字花园，不断积累纯文本的数字资产。

如今，AI 的应用，已经是基本能力，所以，本篇不是技术文，但我仍然放在了「习艺」之中。

感谢这个时代。
